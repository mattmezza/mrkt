# mrkt v1 internal contracts

Go module github.com/mattmezza/mrkt. Coordinator owns dependencies and internal/manifest. Core worker exclusively owns database schema and internal/engine. No worker changes another owner's files; report dependency needs to coordinator. Workers do not spawn agents.

## Application surface

Engine exposes `Open(Config) (*Engine,error)`, `Close() error`, `Do(context.Context, Authority, Operation) (any,error)`, `Tick(context.Context) error`. Authority has Project string, Admin bool, Scopes []string. Operation has Project, Resource, Action, ID, Key string; Input json.RawMessage; Limit int; Cursor string. Error is *engine.Error with Code, Message string and Status int. Resource/action dispatch is shared by REST and UI; unknown operations return 404/400, never success. Authentication is handled by engine `Authenticate(ctx,token) (Authority,error)`; initial hashed admin token is provisioned only on explicit initialization.

Config fields: DBPath string, Initialize bool, Recovery bool, AdminToken string, PublicURL string, Development bool, Artifacts artifact.Store, Sender mail.Sender, EncryptionKey []byte, Now func() time.Time. Server boot env wiring is coordinator-owned. Engine owns all SQLite configuration and migrations. Use a single connection writer and no transactions over external I/O. Mark dispatching before SMTP; expired dispatch attempts become uncertain, never automatically retried. Fresh startup must fail without existing DB or explicit init.

REST: `/api/v1/projects` GET/POST uses resource projects list/create. `/api/v1/projects/{project}/{resource}` GET list, POST create. `/api/v1/projects/{project}/{resource}/{id}` GET get, DELETE delete. `/api/v1/projects/{project}/{resource}/{id}/{action}` POST explicit action; singleton operations use id `_`. Global `/api/v1/installation/{action}` POST and `/api/v1/installation` GET. Header Idempotency-Key maps to Key. JSON body strict per operation. Lists return `{items:[],next_cursor:""}`. Errors `{error:{code,message}}`. Page size default 50 max 200.

Resources: projects, tokens, contacts, lists, releases, events, enrollments, broadcasts, deliveries, webhooks, webhook-deliveries, domains, transports, consent, operations. Actions include plan, deploy, rollback, confirm, unsubscribe, pause, resume, cancel, explain, simulate, replay. Public HTTP routes `/public/{project}/subscribe`, `/public/{project}/confirm`, `/public/{project}/unsubscribe` call explicit engine public operations with validated challenge. Tokens are opaque random; generic subscribe response never reveals token. Confirmation token appears only inside capture SMTP email. Public asset GET `/assets/{project}/{hash}/{name}` requires explicit persisted inventory approval before artifact fetch.

Deploy body `{manifest: <manifest object>, expected_release: "", allow_destructive: false}`; manifest references preuploaded hashes. Artifact PUT `/api/v1/projects/{project}/artifacts/{sha256}` accepts bounded raw body with Content-Type. Store Put validates actual digest/size; engine deployment verifies each reference before activating. Local CLI reads YAML then uploads each inventory file, computes hashes and deploys. Plan operation same body dry-run. Rollback body `{release_id,expected_release}`.

## Artifact/mail interfaces (infrastructure worker defines)

`artifact.Store`: Put(ctx context.Context, project, hash, contentType string, size int64, body io.Reader) error; Get(ctx context.Context, project, hash string) (io.ReadCloser,error); Stat(ctx context.Context, project, hash string) (artifact.Info,error). Info has Size int64 and ContentType string. S3 config API worker chooses and reports; no production disk backend. Tests may use bounded in-memory implementation owned in artifact package.

`mail.Sender`: Send(context.Context, mail.Message) (mail.Result,error). Message has ID, From, To, Subject, HTML, Text, UnsubscribeURL string and Attachments []mail.Attachment. Attachment has Name, ContentType string and Data []byte. Result has State string (`accepted`, `transient`, `permanent`, `uncertain`) and Detail string. Sender error after DATA starts must be uncertain. Production transport config administrator controlled. Coordinator wires default sender; per-project transport config additions can use optional sender factory later.

## Manifest v1 (coordinator defines)

`manifest.Manifest` has Version int, Project Project, Lists []List, Files []File, Messages map[string]map[string]Content, Sequences []Sequence, Broadcasts []Broadcast. All JSON/YAML field names snake_case. Project: Name, DefaultLocale string; Locales []string. List: ID, Name, Purpose, PolicyVersion string. File: Path, SHA256, ContentType string; Size int64; Public bool. Content: Subject, HTML, Text string (template source paths); Attachments []string. Sequence: ID, List, Event, Entry, Reentry string; Steps []Step; Exit *Condition. Step: ID, Type, Message, Delay, Next, Else string; Condition *Condition. Condition: Field, Op string; Value any. Broadcast: ID, Event, List, Message string. Entry `subscription` or `event`; steps `send`, `delay`, `condition`, `complete`; reentry `once` or `event`. `manifest.Validate(Manifest) error`, `Parse([]byte) (Manifest,error)`, `Digest(Manifest) string`, `ResolveLocale(requested,default string,supported []string) string`, `Render(Content, sources map[string][]byte, variables map[string]any) (Rendered,error)` with Rendered Subject/HTML/Text strings. `manifest.ReadDirectory(dir string) (Manifest,map[string][]byte,error)` reads mrkt.yaml safely and fills file hashes. All required artifacts remain external to live SQLite; manifest structural metadata may be persisted in SQLite.

Template variables keys: Name, Email, Locale, UnsubscribeURL, ConfirmationURL, Attributes, Event. Content sources render with html/template and text/template missingkey=error, bounded output. Runtime worker loads sources from S3 using release Files mapping. Message render frozen in S3 with DB reference before dispatch. Synthetic presets use `.Name` with Name resolved to email localpart if absent.
