# 0.1.0 — first self-hosted release

mrkt combines repository-owned email releases with project-isolated live consent and durable execution. This is a first release, not a claim of production certification or inbox-placement guarantees.

## Included

Strict YAML/JSON contracts, four localized workflow presets, pinned journeys and event broadcasts, bounded simulation/rendering, private S3 sources and frozen renders, SQLite migrations, double opt-in and suppression, CSV operations, authenticated feedback, signed webhooks, a responsive operational UI, CLI, official-SDK MCP, and an installable skill. Runtime configuration supports explicit streams, submission diagnostics, DNS readiness checks, scoped credentials, offline key rotation, and deliberate paused recovery.

The build uses Go 1.27.1 in its production image, htmx 4.0.0, compiled Tailwind 4.3.3, and Alpine CSP 3.17.2. Dependency versions and upstream licenses are checked in. The CSS inliner uses a patched `golang.org/x/net` version rather than its older transitive default.

## Deliberate limits

- One active application and one Litestream owner per database. Outbound execution is serial and rate-limited; no active-active or automatic failover.
- SMTP acceptance can be ambiguous. Such attempts require reconciliation, not blind replay. Generic MTA feedback requires a separately installed signed adapter; SES requires independently provisioned SMTP/SNS resources.
- Disaster recovery may lose transactions newer than the replica. Old unsubscribes, complaints, and accepted messages cannot be reconstructed from the restored database alone. Recovery stays paused until an operator records reconciliation.
- Artifact GC is dry-run-only because the application cannot prove reachability across every retained restore point. No object is automatically deleted. Monitor bucket usage and explicitly manage recovery retention.
- Database retention redacts eligible old event payloads and prunes safe expired operational rows in bounded batches; compact event identities/fingerprints stay to prevent repeated broadcasts. A deletion removes the live contact profile and prevents resubscription through routine upsert/import. Necessary suppression evidence remains. Previously captured emails, immutable rendered artifacts, and retained database backups have their own retention lifecycle; this is not a promise of immediate erasure from every storage system.
- Confirmation wording is fixed, localized application content to prevent public confirmation-email injection. Marketing templates are release-owned. Public preferences and confirmation support English, Italian, and Turkish; per-message marketing locales are declarative.
- Templates permit bounded JSON-like variables, pure date/number formatting, and simple conditional/iteration constructs. Nested ranges and template invocation are rejected to bound execution even when nothing is emitted. No remote CSS imports, scripts, filesystem, shell, or network template functions.
- CSV imports are bounded batches and cannot grant confirmed consent. Secret-creating/rotating operations reject generic replayable idempotency keys; store their once-revealed values securely.
- GitHub branch protection was unavailable for this account's private repository (API returned HTTP 403 requiring a plan upgrade). Visibility remains private; no paid plan or publication was authorized.
